Spreadsheet Bisa Dihitung. Dashboard Harus Bisa Dipercaya.

Lab Power BI — studi kasus FSA dengan data nyata. Kamu mengunduh tiga dataset CSV dari laporan keuangan auditan tahun buku 2024 — KLBF (farmasi), MIKA (rumah sakit), dan BBRI (bank mikro) — lalu membangun dashboard sendiri di Power BI Desktop (gratis): model data, ukuran DAX untuk rasio kunci, visual KPI dan tren, sampai interpretasi triple-lens. Tidak ada file .pbix di modul ini — kamu yang membangunnya, langkah demi langkah, dan itulah latihannya. Semua angka bersumber dari LK konsolidasian auditan FY2024 (komparatif 2023); angka yang terhitung dari LK diberi label [T], angka yang diungkap bank diberi label [B]. Rasio yang tidak bisa dihitung dari kolom CSV yang ada tidak dibuatkan DAX — dicatat sebagai batasan di Langkah 3.

⬇ klbf-fsa.csv — KLBF (Rp penuh) ⬇ mika-fsa.csv — MIKA (Rp penuh) ⬇ bbri-fsa.csv — BBRI (jutaan Rp)

Catatan satuan: KLBF dan MIKA dalam Rupiah penuh; BBRI dalam jutaan Rupiah (persis seperti filing IDX-nya). Jangan campur satuan saat membandingkan antar perusahaan — bandingkan rasio, bukan angka absolut. Baris 2023 BBRI sebagian besar kosong: filing 34 halaman hanya memberi angka 2023 untuk pinjaman gross, total aset, dan ekuitas atribusional — sisanya memang tidak tersedia, bukan hilang.

C · Lab Power BI: Lima Langkah dari CSV ke Dashboard

Langkah 1 Unduh CSV, buka Power BI Desktop (gratis, unduh dari situs resmi Microsoft), Get Data → Text/CSV, pilih satu file. Di jendela pratinjau, cek tipe data tiap kolom sebelum menekan Load: kolom Tahun ubah menjadi Text (supaya 2023/2024 diperlakukan sebagai label kategori, bukan angka yang dijumlahkan), semua kolom nilai menjadi Decimal Number. Kolom kosong (mis. Laba_Usaha KLBF 2023, sebagian besar baris BBRI 2023) biarkan kosong — Power BI membacanya sebagai null, dan fungsi agregasi DAX mengabaikan null. Ulangi untuk ketiga file. Jangan menggabungkan ketiga file menjadi satu tabel di tahap ini — tiap perusahaan punya struktur laporan yang berbeda.

Langkah 2 Model data. Tiap file menjadi satu tabel fakta: klbf-fsa, mika-fsa, bbri-fsa. Tidak ada relasi antar tabel — ketiganya tabel fakta yang berdiri sendiri (perusahaan berbeda, struktur kolom berbeda). Tidak perlu tabel kalender: dataset hanya punya dua tahun, dan kolom Tahun sudah berfungsi sebagai dimensi waktu. Bila kamu ingin satu halaman dashboard perbandingan, buat tabel dimensi Perusahaan sederhana (kolom: Perusahaan, Sektor) dan gabungkan ketiga fakta ke satu tabel panjang dengan kolom tambahan Perusahaan — tetapi ukuran DAX per perusahaan di bawah ini ditulis per tabel fakta, supaya tiap rumus bisa dilacak ke satu file CSV.

Langkah 3 Ukuran DAX. Tulis tiap ukuran di bawah ini di panel New measure (klik kanan tabel → New measure). Penjelasan tiap fungsi menyertai rumusnya. Semua rumus mengacu ke nama kolom CSV yang kamu unduh — bila nama kolom di file-mu berbeda, sesuaikan nama kolomnya, bukan angkanya. Format hasil ukuran rasio sebagai Percentage (2 desimal) atau Decimal number (2 desimal) untuk Current Ratio dan D/E.

Ukuran DAX — KLBF & MIKA (kolom KLBF; padanan MIKA di catatan)

Untuk MIKA, ganti Penjualan_Neto → Pendapatan_Bersih, Beban_Pokok_Penjualan → Beban_Pokok_Pendapatan, Piutang_Usaha_Neto → Piutang_Usaha, Persediaan_Neto → Persediaan. MIKA tidak punya kolom Beban_Penjualan / Beban_Umum_Administrasi / Beban_Riset_Pengembangan terpisah — ketiganya sudah menyatu di Beban_Usaha.

Gross Margin =
DIVIDE (
    SUM ( 'klbf-fsa'[Laba_Bruto] ),
    SUM ( 'klbf-fsa'[Penjualan_Neto] )
)
-- DIVIDE(a, b) = a / b, tetapi mengembalikan BLANK bila b = 0 (bukan error).
-- SUM menjumlahkan kolom dalam konteks filter aktif (mis. Tahun = 2024).
-- KLBF 2024: 39,71% | MIKA 2024: 53,68%
Current Ratio =
DIVIDE (
    SUM ( 'klbf-fsa'[Total_Aset_Lancar] ),
    SUM ( 'klbf-fsa'[Total_Liabilitas_Jangka_Pendek] )
)
-- Aset lancar dibagi liabilitas jangka pendek: kemampuan bayar utang jangka pendek.
-- KLBF 2024: 4,11x | MIKA 2024: 4,74x. Di atas 1,0x = aset lancar menutup utang lancar.
Net Margin (Atribusi) =
DIVIDE (
    SUM ( 'klbf-fsa'[Laba_Bersih_Atribusi_Pemilik_Induk] ),
    SUM ( 'klbf-fsa'[Penjualan_Neto] )
)
-- Laba yang menjadi hak pemegang saham induk, bukan laba total (ada kepentingan
-- nonpengendali kecil di KLBF/MIKA). KLBF 2024: 9,93% | MIKA 2024: 23,52%
ROE (Ekuitas Akhir) =
DIVIDE (
    SUM ( 'klbf-fsa'[Laba_Bersih_Atribusi_Pemilik_Induk] ),
    SUM ( 'klbf-fsa'[Total_Ekuitas] )
)
-- ROE versi sederhana: penyebut ekuitas akhir tahun yang sama.
-- KLBF 2024: 13,18% | MIKA 2024: 15,64%. Cocok dengan benchmark [hitungan].
ROE (Rata-Rata Ekuitas Total) =
DIVIDE (
    SUM ( 'klbf-fsa'[Laba_Bersih_Atribusi_Pemilik_Induk] ),
    AVERAGEX (
        VALUES ( 'klbf-fsa'[Tahun] ),
        CALCULATE ( SUM ( 'klbf-fsa'[Total_Ekuitas] ) )
    )
)
-- AVERAGEX(VALUES(Tahun), ...) = rata-rata ekuitas per tahun dalam filter aktif.
-- CALCULATE mengubah konteks baris menjadi konteks filter per tahun.
-- KLBF 2024: 13,58% | MIKA 2024: 16,46%.
-- PERHATIAN: ini memakai TOTAL ekuitas. ROE headline analis (KLBF 14,66%,
-- MIKA 18,61%) memakai rata-rata EKUITAS PEMILIK INDUK — angka itu tidak ada
-- di CSV, jadi headline tersebut TIDAK bisa direplikasi dari dataset ini.
NPM DuPont =
DIVIDE (
    SUM ( 'klbf-fsa'[Laba_Bersih_Atribusi_Pemilik_Induk] ),
    SUM ( 'klbf-fsa'[Penjualan_Neto] )
)

Asset Turnover DuPont =
DIVIDE (
    SUM ( 'klbf-fsa'[Penjualan_Neto] ),
    AVERAGEX (
        VALUES ( 'klbf-fsa'[Tahun] ),
        CALCULATE ( SUM ( 'klbf-fsa'[Total_Aset] ) )
    )
)

Equity Multiplier DuPont =
DIVIDE (
    AVERAGEX (
        VALUES ( 'klbf-fsa'[Tahun] ),
        CALCULATE ( SUM ( 'klbf-fsa'[Total_Aset] ) )
    ),
    AVERAGEX (
        VALUES ( 'klbf-fsa'[Tahun] ),
        CALCULATE ( SUM ( 'klbf-fsa'[Total_Ekuitas] ) )
    )
)

ROE DuPont = [NPM DuPont] * [Asset Turnover DuPont] * [Equity Multiplier DuPont]
-- Tiga faktor DuPont sebagai tiga ukuran terpisah, lalu dikalikan.
-- Tanda [Nama Ukuran] memanggil ukuran lain — DAX menghitungnya dalam konteks
-- filter yang sama. KLBF 2024: 9,93% x 1,16 x 1,18 = 13,58% (cocok dengan
-- ROE rata-rata ekuitas total di atas — bukti internal bahwa modelmu konsisten).
-- MIKA 2024: 23,52% x 0,63 x 1,12 = 16,46%.
Debt to Equity =
DIVIDE (
    SUM ( 'klbf-fsa'[Total_Liabilitas] ),
    SUM ( 'klbf-fsa'[Total_Ekuitas] )
)
-- KLBF 2024: 0,20x | MIKA 2024: 0,13x. Rendah di keduanya: imbal hasil datang
-- dari operasi, bukan leverage.

Kualitas Laba (CFO / Laba) =
DIVIDE (
    SUM ( 'klbf-fsa'[Kas_Neto_Operasi] ),
    SUM ( 'klbf-fsa'[Laba_Bersih_Total] )
)
-- Di atas 1,0 = kas operasi mendahului laba akrual (kualitas laba sehat).
-- KLBF 2024: 1,47x | MIKA 2024: 1,41x.

Ukuran DAX — BBRI (bank; kolom bbri-fsa, satuan jutaan Rp)

Bank tidak dianalisis dengan gross margin atau current ratio — bahan bakunya adalah bunga dan dana pihak ketiga. Empat ukuran di bawah ini semuanya bisa dihitung dari kolom CSV; tiga rasio bank lain yang tidak bisa dihitung ada di tabel batasan setelah blok DAX.

CASA Ratio =
DIVIDE (
    SUM ( 'bbri-fsa'[Giro] ) + SUM ( 'bbri-fsa'[Tabungan] ),
    SUM ( 'bbri-fsa'[Simpanan_Nasabah_DPK] )
)
-- Dana murah (giro + tabungan) dibagi total simpanan nasabah (DPK).
-- BBRI 2024: 67,3% [T] — fondasi pendanaan murah bank mikro.

LDR (Hitung Sendiri) =
DIVIDE (
    SUM ( 'bbri-fsa'[Pinjaman_Diberikan_Gross] ),
    SUM ( 'bbri-fsa'[Simpanan_Nasabah_DPK] )
)
-- Kredit dibagi DPK, definisi hitung-sendiri dari kolom CSV.
-- BBRI 2024: 95,1% [T]. BUKAN 88,85% [B] yang diungkap bank — lihat batasan.
Cost of Credit (CoC) =
DIVIDE (
    SUM ( 'bbri-fsa'[Beban_CKPN_Aset_Produktif] ),
    AVERAGEX (
        VALUES ( 'bbri-fsa'[Tahun] ),
        CALCULATE ( SUM ( 'bbri-fsa'[Pinjaman_Diberikan_Gross] ) )
    )
)
-- Beban pencadangan dibagi rata-rata pinjaman gross.
-- BBRI 2024: 3,35% [T] (bank ungkap 3,2% — selisih definisi denominator).

ROA Bank =
DIVIDE (
    SUM ( 'bbri-fsa'[Laba_Bersih] ),
    AVERAGEX (
        VALUES ( 'bbri-fsa'[Tahun] ),
        CALCULATE ( SUM ( 'bbri-fsa'[Total_Aset] ) )
    )
)
-- BBRI 2024: 3,06% [B=T] — cocok persis dengan angka yang diungkap bank.

ROE Bank (Atribusi, Rata-Rata) =
DIVIDE (
    SUM ( 'bbri-fsa'[Laba_Bersih_Atribusi_Pemilik_Induk] ),
    AVERAGEX (
        VALUES ( 'bbri-fsa'[Tahun] ),
        CALCULATE ( SUM ( 'bbri-fsa'[Ekuitas_Atribusi_Pemilik_Induk] ) )
    )
)
-- BBRI 2024: 19,14% [T] (bank ungkap 19,01% — selisih 0,13pp, definisi
-- denominator yang sedikit berbeda; keduanya dihitung dari angka yang sama).

Langkah 4 Visual. Susun satu halaman per perusahaan, lalu satu halaman perbandingan: kartu KPI (Gross Margin, Current Ratio, ROE, plus satu ukuran bank per halaman BBRI), line chart tren 2023→2024 untuk tiap rasio (dua titik saja — jujur soal keterbatasan: tren dua titik bukan tren, ia hanya arah), bar chart perbandingan KLBF vs MIKA untuk rasio yang sama definisinya (gross margin, net margin, current ratio, D/E — jangan bandingkan rasio bank dengan rasio industri), dan conditional formatting untuk red flag: contoh aturan — Current Ratio < 1,5x berwarna merah (tidak ada yang kena di dataset ini), CoC BBRI > 3% berwarna kuning (kena: 3,35%), Kualitas Laba < 1,0x berwarna merah (tidak ada yang kena). Tambahkan slicer Tahun di tiap halaman. Aturan kartu KPI: satu kartu = satu ukuran + label definisi singkat — kartu tanpa definisi adalah angka tanpa arti.

Langkah 5 Interpretasi & batasan. Baca dashboard-mu dari tiga lensa (contoh pembacaan ada di Case D di bawah). Dan ingat batasan yang paling penting: Power BI memvisualkan, bukan memverifikasi — bila CSV salah ketik satu digit, dashboard tetap tampil rapi dan salah. Selalu cocokkan satu kartu KPI dengan LK auditan sebelum mempercayai dashboard. Dataset ini hanya dua tahun: cukup untuk arah, tidak cukup untuk menyimpulkan tren. Dan tiga perusahaan ini tidak bisa diringkas menjadi satu peringkat — farmasi, rumah sakit, dan bank menjual risiko yang berbeda.

Buktikan hitunganmu — enam rasio di bawah ini harus cocok dengan kartu KPI di dashboard-mu. Ketik jawabanmu (persen tanpa tanda %, Current Ratio sebagai desimal — koma desimal boleh ditulis dengan koma atau titik).

D · Case: "Dashboard Selesai — Sekarang, Apa Vonismu?"

Kamu analis. Dashboard Power BI-mu sudah jadi: KLBF — gross margin 39,71%, current ratio 4,11x, ROE (ekuitas akhir) 13,18%, kualitas laba 1,47x; MIKA — gross margin 53,68%, current ratio 4,74x, ROE 15,64%; BBRI — CASA 67,3%, LDR hitung-sendiri 95,1% (bank: 88,85%), CoC 3,35%, ROA 3,06%, ROE 19,14%. NIM 7,74% dan NPL 2,78% tampil di kartu KPI sebagai angka [DIUNGKAP BANK] — tanpa ukuran DAX, karena penyebutnya tidak ada di CSV. Seorang rekan berkata: "Dashboard sudah lengkap — semua rasio ada, tinggal putuskan beli atau tidak." Tugasmu: tulis verdict — apa yang bisa dashboard ini putuskan, apa yang tidak bisa, dan verifikasi apa yang masih kurang — dari tiga lensa.

Rubrik self-check

Tulis dulu jawabanmu di atas — baru buka panel ini. Centang yang sudah kamu penuhi:

Contoh jawaban model

Lensa investasi: dashboard ini cukup untuk menyaring, tidak cukup untuk membeli. MIKA paling menarik di layar: gross margin 53,68% dan net margin 23,52% (2024) jauh di atas KLBF (39,71% dan 9,93%) — tetapi keduanya menjual produk berbeda (jasa RS vs barang farmasi), jadi selisih margin adalah perbedaan bisnis, bukan keunggulan. BBRI ROE 19,14% tertinggi, tetapi dengan dividen 92,7% dari laba — hampir seluruh laba dibagikan, pertumbuhan ekuitas organik tipis. Satu hal yang membunuh tesis "MIKA layak dibeli dari dashboard ini": dashboard dua tahun tidak menunjukkan apakah margin RS datang dari tarif naik, hunian membaik, atau tempat tidur baru — LK tidak memecahnya, dan tanpa itu saya tidak tahu apakah margin bisa bertahan. Keputusan: TUNGGU — dashboard dipakai untuk shortlist, valuasi butuh data di luar dashboard.

Lensa kredit: ketiga neraca nyaman dibaca dashboard: current ratio KLBF 4,11x dan MIKA 4,74x, D/E 0,20x dan 0,13x — risiko gagal bayar jangka pendek praktis tidak terlihat. BBRI beda ukuran: CAR 26,63% [DIUNGKAP BANK] memberi buffer besar, tetapi CoC 3,35% naik dari 2,4% tahun sebelumnya sementara NPL turun ke 2,78% — bank memprovisioning ke depan, dan dashboard ini tidak bisa menjawab apakah itu kehati-hatian atau ada yang belum terlihat di angka NPL. Keputusan: APPROVE bersyarat untuk KLBF/MIKA; untuk BBRI, minta rincian write-off dan komposisi kredit bermasalah sebelum memakai NPL 2,78% sebagai bukti kualitas kredit.

Lensa forensik: tiga verifikasi sebelum percaya dashboard: (1) cocokkan satu kartu KPI ke LK auditan — mis. CASA 67,3% = (giro Rp374.554.340 juta + tabungan Rp544.426.947 juta) ÷ DPK Rp1.365.450.104 juta — bila satu kartu cocok, model DAX-mu benar; bila tidak, cari salah ketik di CSV dulu, bukan di DAX; (2) tanyakan definisi di balik dua LDR — 95,1% hitung-sendiri vs 88,85% bank — sebelum memakai salah satunya untuk vonis likuiditas; (3) satu temuan yang membuat saya menolak dashboard mentah-mentah: kartu KPI NIM 7,74% tanpa ukuran DAX dan tanpa penyebut yang bisa diverifikasi — angka yang tidak bisa dihitung ulang dari data adalah klaim, bukan bukti. Thesis testing: bukti penguat = tiap kartu KPI bisa dihitung ulang dari CSV; bukti pematah = satu kartu yang angkanya tidak terlacak ke LK.

Contoh di atas bukan kunci jawaban — ia menunjukkan bentuk jawaban yang lolos rubrik: vonis + angka + risiko + tiga lensa. Nilai sendiri: berapa dari 4 checklist yang tercentang di jurnalmu?
